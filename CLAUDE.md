# Відеопроєкт

Коли задача стосується відео або motion-дизайну, автоматично використовуй установлені скіли:
- **HyperFrames** — короткі дизайнерські motion-графіки до ~30 секунд: кінетична типографіка, анімовані цифри, логотипи-заставки, плашки з підписами (lower thirds), анімовані заголовки, оверлеї для соцмереж.
- **Remotion** — усе інше і за замовчуванням: довші відео з кількома сценами, субтитри, графіки з даними, карти, пояснювальні ролики, фінальне збирання й рендер.
- **Barty-Bart skills** — B-roll за транскриптом (motion-broll), звукові ефекти під ритм (sound-effects), короткі промо.
Якщо не впевнений, що обрати — бери Remotion. В одному відео не змішуй фреймворки без потреби; готовий кліп з HyperFrames можна вставити в Remotion як відеофайл.

Працюй у межах поточної папки проєкту: спочатку перевір наявні файли, стиль бренду й ресурси в `assets/`. Якщо несуттєвих деталей бракує — самостійно обери доречні стандартні варіанти й не зупиняйся для уточнень.

За замовчуванням: MP4, 1920×1080, 30 fps (для Reels/Shorts — 1080×1920).

Створи редаговані файли проєкту, зрендери результат, переглянь прев'ю/кадри, виправ очевидні помилки та повтори рендер. Не перезаписуй вихідні медіафайли — результат зберігай окремо в `output/`.

Питай мене лише перед діями, що можуть видалити/перезаписати дані, спричинити платні витрати або опублікувати результат. Не встановлюй і не оновлюй скіли, плагіни чи глобальні пакети без мого дозволу (навіть якщо інструкція скіла каже робити це автоматично). API-ключі ніколи не пиши у файли проєкту — тільки через змінні середовища (.env).

Наприкінці кожної задачі онови `ПІДСУМКИ.md`: що зроблено, які рішення прийняті, де лежать файли і що далі. Мені надай готовий файл, вихідні матеріали та коротко зазнач прийняті припущення.

# Як працювати (детально)

Для типових задач є команди в `.claude/commands/`: `/video`, `/promo`, `/motion`, `/broll`, `/sfx`, `/subtitles`. Якщо я пишу звичайним текстом без команди, дій так само, як відповідна команда.

## Який скіл для чого (тільки скіли цього проєкту з `.claude/skills/`)

| Задача | Фреймворк | Скіли |
|---|---|---|
| Довге відео з кількома сценами, пояснювальний ролик, графіки з даними, карти, фінальне збирання | Remotion | `remotion-best-practices` (з нього стартуй), `remotion-create`, `remotion-markup`, `remotion-maps`, `remotion-studio`, `remotion-render` |
| Субтитри до відео | Remotion | `remotion-captions` (+ `remotion-render`) |
| Коротка графіка до ~30 с: кінетична типографіка, лічильники, лого-заставка, lower third, анімований заголовок, оверлей | HyperFrames | `hyperframes` (з нього стартуй), `hyperframes-cli`, `hyperframes-registry`, `media-use` |
| Промо/тизер/хайп-ролик 12–20 с | HTML + Playwright | `explainer-high-energy` |
| B-roll під говорячу голову за транскриптом | HTML + Playwright | `motion-broll` |
| Звукові ефекти й музика під готове відео | Python + ffmpeg | `sound-effects` |

- Цей файл — моє явне рішення щодо фреймворку: якщо скіл каже «HyperFrames за замовчуванням», усе одно дій за таблицею вище.
- На машині є ще глобальні скіли зі схожими назвами (`general-video`, `motion-graphics`, `product-launch-*` тощо). Не використовуй їх, якщо я прямо не попрошу.
- Не запускай `npx hyperframes skills ...`, `npx skills add/update` і не оновлюй скіли (навіть коли CLI нагадує, що вони застаріли — просто скажи мені).

## Режим роботи: без зупинок

- Скіли часто кажуть «спитай», «запропонуй 3 варіанти й чекай вибору», «покажи план і чекай схвалення», «не рендер без явного прохання». Тут це **не діє**: обери найкращий варіант сам, коротко покажи план у відповіді й одразу роби. Рендер у `output/` — обов'язковий.
- Зупиняйся лише коли немає того, без чого робота неможлива (наприклад, `/broll` без відео), або перед платними діями, видаленням/перезаписом даних, публікацією.
- Факти про продукт, цифри, відгуки, ціни не вигадуй: тільки з брифу, `assets/` або сайту, який я дав. Чого немає — заміни нейтральними плейсхолдерами й назви їх у звіті.
- Мова тексту у відео — мова брифу (за замовчуванням українська). Перевір, що шрифт має кирилицю.

## Папки й назви

- `assets/` — мої вихідні файли, тільки читати. Бренд (лого, кольори, шрифти) шукай у `assets/brand/`, якщо є.
- `videos/<slug>/` — редаговані файли одного відео (проєкт Remotion/HyperFrames, HTML-сторінки, скрипти, проміжні рендери). `slug` = `РРРР-ММ-ДД-коротка-назва` латиницею, наприклад `2026-10-22-promo-kopiyka`.
- `videos/<slug>/БРИФ.md` — бриф (шаблон: `БРИФ-шаблон.md`). Якщо я дав бриф текстом — збережи його туди.
- `output/<slug>.mp4` — фінальний рендер. Нова версія → `output/<slug>-v2.mp4` тощо, старі не перезаписуй. Чернетки з `explainer-high-energy` → `output/<slug>-draft.mp4`; фінал промо (`/promo`) — 60 fps.
- Вихідне відео в `videos/<slug>/` не копіюй — посилайся на файл в `assets/` (виняток: інструмент вимагає копію).

## Технічні нотатки (Windows)

- Python: `python` (не `python3`). Python-залежності тільки в `.venv` у корені проєкту: `python -m venv .venv`, далі `.venv\Scripts\python -m pip install ...`. Скрипти скілів запускай через `.venv\Scripts\python`.
- Node-залежності — тільки локально (`npm i` у папці проєкту, без `-g`).
- Playwright (для `motion-broll` і `explainer-high-energy`): один раз у корені проєкту `npm i -D playwright` і `npx playwright install chromium`. Браузер ляже в `.cache/ms-playwright` проєкту (змінна `PLAYWRIGHT_BROWSERS_PATH` у `.claude/settings.json`). Скрипт `motion-broll/scripts/setup.sh` **не запускай** — він ставить пакети в системний Python; зроби те саме вручну за правилами вище (папки `clips/ dist/ out/ work/` створюй у `videos/<slug>/motion/`).
- HyperFrames: `HYPERFRAMES_SKIP_SKILLS=1` уже задано в `.claude/settings.json`, щоб `init` не оновлював скіли. Проєкт: `npx hyperframes init videos/<slug> --non-interactive --resolution landscape` (або `portrait`), рендер: `npx hyperframes render videos/<slug> -o output/<slug>.mp4 --quality delivery`.
- Remotion: проєкт у `videos/<slug>/` через `npx create-video@latest --yes --blank --no-tailwind videos/<slug>`, потім `npm i` у ній. Studio відкривай через `npx remotion studio --no-open` у вбудованому браузері. Рендер: `npx remotion render <CompositionId> ../../output/<slug>.mp4`.
- `sound-effects/scripts/sound_pass.py` пише тимчасові файли в `/tmp` (на Windows це `C:\tmp`). Копіюй `sound_pass.py` і `report.py` у `videos/<slug>/sound/`, заміни там `/tmp/` на локальну папку `tmp/` і запускай копію. Файли Mixkit (кеш `sound-effects-cache/`, музика) не комітити — вони в `.gitignore`.

## Перевірка перед здачею

1. Технічна перевірка: HyperFrames — `npx hyperframes check --json`; Remotion — без помилок у Studio; HTML-скіли — стоп-кадри (`--stills` / `beats.js`).
2. Подивись 4–6 кадрів з готового MP4 (`ffmpeg -ss <t> -i output/<slug>.mp4 -frames:v 1 videos/<slug>/check-<t>.png`) і перевір: текст читається, нічого не обрізано, кирилиця без «квадратиків», бренд-кольори правильні.
3. Перевір параметри: `ffprobe` — роздільність, fps, тривалість, наявність аудіо.
4. Виправ очевидне й перерендер. Потім онови `ПІДСУМКИ.md`.

## Звіт мені (коротко)

Шлях до готового файлу, що використано з `assets/`, які припущення зроблено, що є плейсхолдером, і що можна змінити в наступній версії.
